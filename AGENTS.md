# AGENTS.md — GitHub Copilot Premium Quota Monitor for IntelliJ

## Project Overview
IntelliJ Platform plugin (Kotlin, Java 21) that monitors GitHub Copilot premium quota via a status bar widget. Built with the [IntelliJ Platform Gradle Plugin v2](https://plugins.jetbrains.com/docs/intellij/tools-intellij-platform-gradle-plugin.html) targeting IntelliJ Community (IC) 2025.2.4+.

## Essential Build Commands
```bash
# Run plugin in a sandboxed IDE instance
./gradlew runIde

# Build distributable ZIP
./gradlew buildPlugin

# Verify plugin against target IDE
./gradlew verifyPlugin

# Run tests
./gradlew test
```
> On Windows behind a corporate HTTPS-inspection proxy, SSL is handled via `systemProp.javax.net.ssl.trustStoreType=Windows-ROOT` in `gradle.properties`. The `verifyPlugin` task re-passes these flags explicitly (see `build.gradle.kts`).

## Architecture & Key Components

```
services/
  AuthService.kt       — OAuth 2.0 Device Flow auth; tokens stored in IntelliJ PasswordSafe
  PluginService.kt     — Quota fetch/cache; publishes to QuotaNotifier.QUOTA_TOPIC
  AuthStateNotifier.kt — MessageBus topic: AUTH_TOPIC (auth state changes)
  QuotaNotifier.kt     — MessageBus topic: QUOTA_TOPIC (quota data updates)
statusbar/
  StatusBarWidget.kt   — UI widget; subscribes to both topics; triggers refresh on double-click
  StatusBarWidgetFactory.kt
settings/
  PluginSettings.kt    — PersistentStateComponent → ghcp-premium-quota-monitor-settings.xml
  PluginSettingsConfigurable.kt  — Settings → Tools panel with cross-field validation
  SettingsChangeNotifier.kt      — MessageBus topic for settings changes
ui/
  DeviceAuthFlowDialog.kt        — Modal dialog for OAuth device code polling
startup/
  SignInStartupActivity.kt       — Shows sign-in on first run (ProjectActivity)
i18n/
  Messages.kt          — Singleton wrapper around ResourceBundle; use Messages.get(key) / Messages.format(key, args)
PluginInfo.kt          — Runtime version from /plugin-version.properties (generated by Gradle processResources)
```

## Communication Pattern (MessageBus)
All cross-component communication uses IntelliJ's MessageBus — never direct references between UI and services:
1. `AuthService` → publishes `AUTH_TOPIC` → `PluginService` re-fetches quota
2. `PluginService` → publishes `QUOTA_TOPIC` → `StatusBarWidget` re-renders
3. `PluginSettings` changes → publishes `SettingsChangeNotifier` topic → widget re-renders

## API & Quota Parsing
`PluginService` calls `{apiBaseUrl}/copilot_internal/user` and tries four JSON formats in order (modern → legacy → nested → flat) — see `parseQuota()`. Always returns a `QuotaResult` sealed class: `Loading | Available | Unlimited | NoAccount | Error`.

## GitHub Enterprise Server (GHE) support
`AuthService` exposes `baseUrl()`, `apiBaseUrl()` and `effectiveClientId()`, computed at call time from `PluginSettings` (`useGitHubEnterprise`, `gitHubEnterpriseUrl`, `gitHubEnterpriseClientId`). When GHE is disabled these resolve to `https://github.com` / `https://api.github.com` / the public `AuthService.CLIENT_ID`; when enabled, to `{gitHubEnterpriseUrl}` / `{gitHubEnterpriseUrl}/api/v3` / the custom Client ID. `PluginService` and the "Open Dashboard" action reuse these helpers instead of hardcoded hosts. Changing the GHE configuration in Settings clears any stored credentials (`AuthService.clearAuthentication()`) since a token is bound to a single host.

## Conventions
- **Services** are `@Service(Service.Level.APP)` with a `getInstance()` companion static.
- **i18n**: all user-facing strings go in `src/main/resources/messages.properties` and all `messages_*.properties` siblings. Use `Messages.get("key")` or `Messages.format("key", arg)` — never hardcode strings.
- **Version**: never read plugin version from `PluginManager`; use `PluginInfo.version` (reads `/plugin-version.properties` injected at build time).
- **HTTP**: always call `conn.disconnect()` in a `finally` block; always use `.use {}` for streams.
- `instrumentCode` and `instrumentTestCode` tasks are **disabled** (JBR `Packages` dir incompatibility).
- `untilBuild` is intentionally **not set** in `build.gradle.kts` to remain compatible with future IDE versions.
